Two ways a stock count goes wrong

These run on a separate sample item, not on the stock above. Run a case the usual way first, then switch to CountOnce and run it again.

Run each case with

Two people take the last unit at the same momentOne unit is left, and Aisha and Bilal both scan it out.

The usual way reads the stock, then saves the change. Between the two steps is a gap in which a second scan can read the same stock. Here the gap is stretched to 0.2 seconds, so the mistake shows every time. CountOnce checks and changes the stock in one step, so there is no gap.

A phone sends the same scan twiceFive in stock. Aisha scans one out, but her signal drops before the reply comes back, so the phone sends the scan again.

Each scan carries an id made on the phone. The usual way counts every send; CountOnce sees the same id again and counts the scan once.
